# Provider Adapter Contract — Presenter Video

## 1. Purpose

Provider adapters isolate vendor/model/runtime details from Pyre's semantic capability layer.

The domain layer requests:

```text
media.voice.synthesize
media.presenter.generate
media.lipsync.repair
media.asr.word_timestamps
media.timeline.compose
media.video.encode
```

The adapter layer decides how to execute that capability against a specific runtime/provider.

---

## 2. Required interface

Conceptual interface:

```ts
export interface ProviderAdapter<TRequest, TResult> {
  readonly adapterId: string;
  readonly provider: string;
  readonly capabilities: readonly string[];

  describe(): Promise<ProviderDescriptor>;
  supports(request: CapabilityRequest): Promise<SupportDecision>;
  estimate(request: TRequest): Promise<CostEstimate>;
  execute(request: TRequest, context: ExecutionContext): Promise<ProviderRun>;
  poll(run: ProviderRun, context: ExecutionContext): Promise<ProviderRun>;
  cancel(run: ProviderRun, context: ExecutionContext): Promise<ProviderRun>;
  collect(run: ProviderRun, context: ExecutionContext): Promise<TResult>;
  normalizeError(error: unknown): ProviderError;
}
```

Not every backend supports native polling/cancel; adapters must still implement deterministic semantics:

- synchronous backend: `execute` may return `succeeded`;
- non-cancellable backend: `cancel` returns a normalized unsupported decision;
- local worker: task ID is generated by Ginkgo.

Hard-gate response:

```json
{
  "supported": true,
  "reasons": [],
  "constraints": [],
  "requires_approval": []
}
```

Unsupported example:

```json
{
  "supported": false,
  "reasons": ["REGION_NOT_LICENSED"],
  "constraints": ["provider cannot execute in requested destination policy"],
  "requires_approval": []
```

Hard gates run before routing score.

Provider request bodies are sanitized before persistence.

Remove:

- API keys;
- Authorization headers;
- signed URLs;
- temporary credentials;
- raw secrets;
- absolute machine paths unless internal-only and explicitly required.

## 8. Idempotency rules

### Remote asynchronous provider

If a task was submitted and execution is interrupted:

```text
load provider_task_id
→ poll
→ succeeded: collect
→ running: continue poll
→ failed/cancelled: classify
→ only then consider resubmit
```

Never create a new paid job just because the orchestrator restarted.

### Local worker

Use:

```text
run_id + input artifact hashes + adapter version
```

as deduplication evidence.

## 9. Error normalization

All provider errors map to a stable taxonomy:

```text
PROVIDER_UNAVAILABLE
PROVIDER_TIMEOUT
PROVIDER_RATE_LIMIT
PROVIDER_AUTH_ERROR
PROVIDER_BILLING_ERROR
PROVIDER_REJECTED_INPUT
PROVIDER_POLICY_REJECTED
PROVIDER_CAPABILITY_MISMATCH
PROVIDER_OUTPUT_INVALID
PROVIDER_TASK_LOST
LOCAL_RUNTIME_UNAVAILABLE
LOCAL_GPU_OOM
ARTIFACT_UPLOAD_FAILED
ARTIFACT_DOWNLOAD_FAILED
UNKNOWN_PROVIDER_ERROR
```

Normalized error:

```json
{
  "code": "PROVIDER_RATE_LIMIT",
  "message": "Provider rate limit reached",
  "retryable": true,
  "retry_after_ms": 30000,
  "provider_code": "429",
  "safe_details": {}
}
```

## 10. Retry policy

Retry is controlled by orchestrator policy, not by opaque SDK behavior.

Suggested defaults:

| Error | Retry | Provider switch |
|---|---:|---:|
| timeout | yes | after same-provider retry |
| rate limit | yes | optional |
| auth | no | no |
| billing | no | no |
| invalid input | no | no |
| GPU OOM | yes with downgraded local profile | yes if same semantics |
| output invalid | repair/retry based on defect | yes after classification |
| policy reject | no | only if alternate policy passes |

Adapters may use transport-level retries for safe GET/poll calls but must not silently duplicate billable create operations.

```json
    "presenter_asset_id": "ast_...",
```

```text
workflow_key
version
sha256
required_models
required_custom_nodes
input_mapping
output_mapping
benchmark_status
```

## 13. Health

Provider health states:

```text
healthy
degraded
unavailable
disabled
policy_blocked
```

Health can include:

- API ping;
- auth check;
- queue depth;
- GPU availability;
- model loaded status;
- recent success rate;
- p95 latency.

Router must never choose `unavailable`, `disabled`, or `policy_blocked`.

---

## 14. Conformance tests

Every adapter must pass the same contract suite:

1. descriptor parses;
2. unsupported input returns normalized reason;
3. estimate is deterministic for fixture;
4. execute returns run record;
5. repeated poll does not duplicate work;
6. secrets are redacted;
7. errors normalize;
8. output artifact exists and matches declared type;
9. cancellation semantics are explicit;
10. adapter never mutates source assets;
11. retryable/non-retryable errors are correctly marked;
12. provider-specific fields do not escape through skill result except evidence metadata.

---

## 15. Production gate

A provider adapter may be `PRODUCTION` only when:

- license reviewed;
- credentials/secrets path reviewed;
- benchmark complete;
- contract suite passes;
- idempotency behavior proven;
- cost estimate validated;
- failure taxonomy mapped;
- observability events emitted;
- rollback/disable switch exists.
